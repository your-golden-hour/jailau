# Проверка первой версии Qwen Coder

Проверен `main` на коммите `f9d42bab2c4ae2264914a45683debb4f06e7b347`.
Исправления и схема подготовлены в отдельной ветке `review/first-scaffold-security`.

## Вывод

Это рабочий каркас демо-интерфейса, а не подключённый сервис поездок.
Для реальных пользователей и production пока не готов. Секретных ключей для
проверки не потребовалось. Cloudflare и облачная Supabase не изменялись.

## Найдено и исправлено

1. **Поездку завершал водитель.** Кнопка перенесена пассажиру, в mock и SQL
   проверяется владелец-пассажир. В SQL переход и +1 к `completed_trips` выполняются
   в одной транзакции; повторный запрос отклоняется.
2. **Принятие обходило фильтр зоны.** Теперь сама операция проверяет одобрение,
   online, зону и места. В PostgreSQL используется условный UPDATE под блокировкой,
   поэтому одна заявка не может получить двух водителей.
3. **Можно было запросить ленту от имени другого водителя**, передав его ID
   в mock-метод. Аргумент удалён: используется текущая сессия.
4. **При регистрации mock принимал роль admin.** Разрешены только passenger/driver.
   В SQL роль администратора назначает только владелец вне браузерной регистрации.
5. **Замена URL скрывала демо-баннер без реального backend.** В этой версии режим
   явно закреплён как демо до появления настоящего адаптера.
6. **Калькулятор игнорировал расход машины.** В карточках теперь используется расход
   из профиля, а не всегда общий. 22 × 1,3 × 7,5 / 100 × 235 = 504,075 ₸ → 504 ₸.
   Контракт исправлен: исходные километры по прямой, коэффициент применяется один раз.
7. **Кэш мог захватывать будущие API-ответы и удалять чужие кэши на том же origin.**
   Теперь кэшируется только список файлов оболочки и очищается только кэш Jailau.
8. Исправлены часть непереведённых текстов и HTML-код казахского языка (`kk`).
   Ключ `kz` в JSON сохранён для совместимости. Демо-данные получили явные названия
   и нерабочие тестовые номера вместо реалистичных мобильных примеров.
9. Добавлены `.gitignore`, инструкция Supabase, SQL, автоматические проверки и
   актуальный статус проекта.

## Что проверено

- SQL исполняется в локальном PostgreSQL через PGlite с ролями anon/authenticated
  и тестовой `auth.uid()`. Проверены RLS, запрет повышения роли/подмены телефона/
  правки счётчика, чужие профили, зоны, одобрение, online, вместимость, видимость
  телефонов, отмена/освобождение и завершение только пассажиром.
- Успешно выполнены 6 автоматических тестов: SQL-набор, mock-сценарий,
  экранирование пользовательского HTML, наличие переводов для статических ключей,
  precache/очистка кэша, запрет кэширования API и офлайн-fallback.
- Просмотрены все 15 доступных исторических файловых объектов первых трёх коммитов.
  Локальная эвристическая проверка токенов и service_role JWT ничего не обнаружила.
  Это не гарантия отсутствия любого возможного секрета или совпадения вымышленных
  данных с реальными людьми. История содержит исходные реалистичные демо-примеры;
  персональные данные не загружались из базы. История не переписывалась.
- На момент проверки GitHub Secret scanning и Push protection включены;
  список предупреждений пуст. Демо-пароль `demo1234` намеренно публичный и
  применим только к mock в памяти; не переносить его в реальные аккаунты.
- Оболочка около 149 КБ до сжатия и 39 КБ при суммировании gzip каждого файла.
  В runtime нет фреймворков, внешних шрифтов и платных API. Тестовые зависимости
  dev-only и в браузер не загружаются.

## Что ещё не проверено / блокирует реальный запуск

- SQL не запускался на вашем Supabase-проекте. Auth JWT, PostgREST и две
  одновременные транзакции независимых сессий требуют облачного теста.
- `js/api.js` остаётся in-memory mock; пароль в нём хранится как тестовая строка.
  Production должен полностью перейти на Supabase Auth; паролей/хешей в публичных
  таблицах или localStorage не будет.
- Нет согласованного безопасного восстановления телефонного аккаунта без SMS.
  Без подтверждения номер может указать посторонний. SQL не является Auth-ban;
  blocked-профиль теряет доступ к данным, но запрет самого входа ещё надо связать
  с Auth/адаптером.
- Нет проверки координат и расстояний демо-сёл. Функция расчёта прямого расстояния
  из координат пока отсутствует: используются введённые километры. Перед реальным
  запуском выбрать точку города и добавить/проверить расчёт по координатам.
- Визуальная проверка на реальном дешёвом Android, замер скорости в медленной сети
  и установка PWA на устройствах не выполнены. Manifest содержит только SVG-иконки;
  для совместимости ещё нужны PNG 192/512 и проверка установки.
- Долгие async-ответы при быстрой смене экранов могут устаревать: при реальном
  адаптере нужен контроль жизненного цикла запросов и обновлений экрана.
- Полная страница условий/конфиденциальности пока отсутствует. Имеется только
  короткий текст «не перевозчик, оплата наличными». До запуска нужны согласие,
  правила хранения/удаления данных и юридическая консультация владельца.
- Номер, который пользователь сам вписал в комментарий/имя/место посадки,
  не защищается скрытием структурированного phone-поля. Добавить понятное
  предупреждение и проверку ввода перед реальными регистрациями.

Ветка `release` не продвигается: сначала закончить интеграцию и проверки выше.
Публикация потребует отдельного подтверждения владельца.
